### 3. Саморез DIN7504M

Статус: реализовано.

Файл:

- `Raluma/backend/engine/slide_calc.py`
- `Raluma/backend/tests/test_slide_calc.py`

Что сделано:

- Старое `lb_count * 7 * Q` заменено на расчет от высоты.
- Новая формула в 1-рядной и 2-рядной ветке:

```text
DIN7504M = RU005 * 2 + ceil((H - 200) / 300) * количество_сторон_RS2081 * Q
```

- На ролики формула осталась прежней: `RU005 * 2`.
- Для `H=2400` получается `8` саморезов на одну сторону `RS2081`.
- Если `RS2081` стоит с двух сторон, получается `16` саморезов на `RS2081`, плюс саморезы на ролики.

Покрыто тестами:

- Без `RS2081` -> только ролики.
- Один `RS2081`, `H=2400` -> ролики + 8.
- Два `RS2081`, `H=2400` -> ролики + 16.
- Два `RS2081`, `H=3000` -> расчет меняется по высоте.
- `quantity=2` умножает часть по `RS2081`.

Что важно проверить ревьюеру:

- Не перепутаны `DIN7504M` и `DIN7504O`.
- Не изменена логика саморезов для `RS1082`.
- В 1 ряду и 2 рядах формула одинаково применена.

### 4. `(чертеж)` в заказе стекла

Статус: реализовано.

Файлы:

- `Raluma/backend/engine/project_documents.py`
- `Raluma/backend/tests/test_documents.py`

Что сделано:

- Заказ стекла больше не ставит `(чертеж)` на всю секцию через общий `_has_glass_drawing(section)`.
- Добавлен слой физических стекол для заказа: расчетные агрегированные строки сначала разворачиваются до панелей, потом снова группируются по `(glass_type, width, height, note)`.
- Для 1 ряда:
  - левая боковая фурнитура помечает левое стекло;
  - правая боковая фурнитура помечает правое стекло;
  - промежуточные стекла не получают `(чертеж)` от боковой фурнитуры;
  - старые общие поля `lock/handle` оставлены fallback-ом для крайних/одиночного стекла.
- Для 2 рядов:
  - боковая фурнитура помечает только боковые стекла;
  - центральная фурнитура (`center_lock`, `center_handle`, центральные защелки) помечает только центральные стекла;
  - левая/правая центральная напольная защелка помечает только соответствующее центральное стекло, если нет общего центрального замка/ручки;
  - промежуточные стекла не получают `(чертеж)` от боковой или центральной фурнитуры.
- Backend явно игнорирует no-op строки фурнитуры вроде `Без замка`, `Без ручки`, `Без ...`, `Нет ...`, чтобы старые/API-данные не создавали ложный `(чертеж)`.
- Маркировка строится по физическим стеклам внутри секции. После текущей правки в документе выводится только `секция,стекло`, без номера проекта.

Покрыто тестами:

- 1 ряд, агрегированная строка `Крайние` с `qty=2`: если замок только слева, `(чертеж)` получает только одно левое стекло, правое и промежуточное остаются без note.
- 2 ряда, все стекла одинакового размера: центральный замок делит одинаковые стекла на две строки - центральные с `(чертеж)` и боковые без note.
- 2 ряда, включена только левая центральная напольная защелка: `(чертеж)` получает только левое центральное стекло.
- Строки `Без замка`/`Без ручки` не создают `(чертеж)`.

Что важно проверить ревьюеру:

- Одинаковые стекла с чертежом и без чертежа не объединяются в одну строку.
- `(чертеж)` не размазывается на всю секцию.
- Если в будущем появится фурнитура, которая относится к конкретному промежуточному стеклу, ее надо будет добавить в этот же слой физического разворачивания.
